# Drawly 已实现功能规格书

> 更新日期：2026-11-02
> 画板 SDK：tldraw 5.6.0

## 1. 应用组成

Drawly 是一个基于 tldraw SDK 的本地部署多人协作画板。当前版本提供账号、画板管理、实时协作、链接分享、评论与 @ 提及、资源上传和本地持久化能力。

系统由以下部分组成：

- Web 前端：React 19、Vite、tldraw SDK。
- 应用服务：Fastify，提供账号、画板、分享、评论成员、资源和链接预览接口。
- 同步服务：`@tldraw/sync-core`，通过 WebSocket 同步画板数据和协作状态。
- 数据存储：SQLite 和本地文件系统，不依赖云端数据库或对象存储。
- 部署方式：本机开发运行或 Docker/Podman 单容器运行。

## 3. 账号与身份

### 3.1 注册

- 用户可在登录页切换到注册模式。
- 注册字段包括显示名称、用户名和密码。
- 用户名仅允许字母、数字和下划线，长度为 3～32 位。
- 用户名不区分大小写，注册时统一转换为小写。
- 用户名在本地系统中唯一。
- 密码长度为 8～128 位。
- 显示名称最长 50 个字符。
- 注册成功后自动建立登录会话并进入画板管理页。
- 系统根据用户 ID 自动分配初始头像颜色。

### 3.2 登录与登录态

- 用户可使用用户名和密码登录。
- 页面初始化时自动检查并恢复有效登录态。
- 未登录用户不能访问画板、分享画板、资源和同步接口。
- 登录会话默认有效期为 30 天。
- 会话令牌通过 HttpOnly Cookie 保存。
- 服务端仅保存会话令牌的 SHA-256 哈希，不保存令牌明文。
- 生产环境 Cookie 启用 `Secure`，并使用 `SameSite=Lax`。

### 3.3 密码安全

- 密码使用 Argon2id 哈希后存储。
- Argon2id 当前参数为：内存成本 19456、时间成本 2、并行度 1。
- 登录失败统一提示“用户名或密码错误”，不暴露用户名是否存在。

### 3.4 个人资料

- 用户可查看用户名、显示名称和头像。
- 用户可修改显示名称。
- 用户可通过颜色选择器修改头像颜色。
- 显示名称和头像颜色会同步用于多人协作光标、成员身份及评论作者。

### 3.5 退出登录

- 用户可通过账号卡片退出登录。
- 退出时服务端删除当前 Session 并清除 Cookie。
- 退出成功后返回登录页。

### 3.6 账号悬浮卡片

- 登录后显示账号悬浮卡片，提供个人资料和退出入口。
- 账号卡片支持拖动。
- 拖动位置保存在浏览器本地，刷新后保持。
- 窗口尺寸变化时会自动限制在可视区域内。

## 5. 画板管理

### 5.1 默认入口

- 用户登录后默认进入画板管理页，而不是进入固定画板。
- 未知前端路由自动返回画板管理页。

### 5.2 新建画板

- 用户可在画板管理页新建画板。
- 画板名称最长 80 个字符。
- 未输入名称时，新建画板使用“未命名画板”。
- 创建成功后自动进入新画板。
- 新画板归当前登录用户所有。

### 5.3 画板分类

- “最近使用”：显示当前用户最近打开过的自有画板和他人分享画板。
- “我的画板”：仅显示当前用户创建且未删除的画板。
- “回收站”：显示当前用户删除的画板。
- 列表按最近打开或最近更新时间排序。
- 画板卡片显示画板名称及最近打开、创建或删除时间。
- 他人分享的画板显示“只读”或“可编辑”权限标识。

### 5.4 打开与最近记录

- 打开自有画板时记录当前用户的最近打开时间。
- 通过分享链接打开画板时记录当前用户、画板和对应分享权限。
- 他人分享画板在首次打开后进入“最近使用”。
- 已关闭的分享链接不会继续出现在接收者的“最近使用”中。

### 5.5 重命名

- 画板所有者可重命名未删除画板。
- 重命名后的画板名称立即用于管理页和画板工作区标题。
- 非所有者不能重命名分享画板。

### 5.6 复制

- 画板所有者可复制未删除画板。
- 副本名称自动添加“副本”后缀，并确保不超过 80 个字符。
- 复制操作会复制画板房间数据库，因此包括图形、页面和评论等房间内容。
- 副本是新的独立画板，拥有新的画板 ID。

### 5.7 删除与恢复

- 删除采用软删除，画板进入回收站。
- 删除画板不会立即删除房间数据库和资源文件。
- 所有者可从回收站恢复画板。
- 恢复后画板重新出现在“我的画板”中。
- 当前版本未提供永久删除入口。

## 6. 多人实时协作

### 6.1 实时同步

- 同一画板的多个登录用户可通过 WebSocket 同步编辑。
- 图形、页面、样式、评论等房间记录实时同步。
- 客户端使用 `@tldraw/sync`，服务端使用 `@tldraw/sync-core`。
- 客户端断线后由 tldraw Sync 负责基础重连和状态恢复。
- 活跃房间在内存中复用；最后一个会话离开后关闭房间和数据库连接。

### 6.2 协作身份

- 协作用户 ID 使用 Drawly 账号 ID。
- 协作显示名称使用账号显示名称。
- 协作颜色使用账号头像颜色。
- 支持 tldraw 默认实时光标、在线协作者显示和跟随能力。
- 个人资料修改后，新的身份信息用于协作展示。

### 6.3 房间访问控制

- 所有 WebSocket 连接必须具有有效登录会话。
- 所有者可通过自有画板地址进入房间。
- 非所有者必须携带有效且匹配当前画板的分享令牌。
- 无权访问、画板已删除或分享已关闭时拒绝建立同步连接。
- 只读分享会话在同步层设置为只读，服务端拒绝写入画板记录和对象记录。

## 7. 分享与权限

### 7.1 分享入口

- 所有者可在画板管理页的画板卡片中打开分享设置。
- 所有者在画板内未选中任何图形时，可通过右键菜单选择“分享画板”。
- 分享入口不会覆盖画板右上方的调色板等原生 UI。

### 7.2 分享类型

- 只读分享：访问者可以查看内容、移动视图、查看协作光标，但不能修改画板或发表评论。
- 可编辑分享：访问者可以实时编辑画板并发表评论。
- 同一画板可同时存在一个有效只读链接和一个有效可编辑链接。
- 重复创建同权限分享时复用已有有效链接。

### 7.3 分享链接操作

- 支持生成并自动复制分享链接。
- 支持再次复制已生成的链接。
- 浏览器剪贴板 API 不可用时使用兼容复制方式。
- 支持分别关闭只读分享或可编辑分享。
- 关闭分享后链接立即失效。
- 关闭分享时，已使用该链接连接的同步会话会被主动断开。

### 7.4 分享访问体验

- 访问分享链接前需要登录 Drawly。
- 分享画板显示画板名称和当前权限。
- 分享画板显示“由某某分享”的所有者信息。
- 分享链接不存在、已关闭、画板已删除或无权访问时显示错误页。
- 分享接收者只能打开画板，不能重命名、复制、删除或管理该画板的分享。

### 7.5 权限矩阵

| 操作 | 所有者 | 可编辑分享 | 只读分享 |
| --- | :---: | :---: | :---: |
| 查看画板 | ✅ | ✅ | ✅ |
| 查看实时协作状态 | ✅ | ✅ | ✅ |
| 修改画板内容 | ✅ | ✅ | ❌ |
| 创建和回复评论 | ✅ | ✅ | ❌ |
| 查看评论 | ✅ | ✅ | ✅ |
| 重命名、复制、删除画板 | ✅ | ❌ | ❌ |
| 创建或关闭分享链接 | ✅ | ❌ | ❌ |

## 8. 评论与 @ 提及

### 8.1 评论创建与展示

- 可在画布位置创建锚定评论图钉。
- 支持查看评论线程和评论侧栏。
- 支持对评论进行回复。
- 支持编辑和删除本人评论。
- 支持将评论线程标记为已解决。
- 支持恢复或查看评论线程状态。
- 支持表情回应，回应数据参与同步和持久化。
- 评论作者显示真实账号名称和头像颜色。

### 8.2 评论编辑能力

- 评论编辑器支持富文本。
- 支持粗体、斜体、列表、链接、代码和高亮等评论格式。
- 评论记录、线程和回应通过 tldraw 对象存储通道实时同步。
- 评论操作不进入普通画板撤销历史，避免画板撤销误修改评论。

### 8.3 @ 提及

- 输入 `@` 可搜索并选择协作成员。
- 候选成员显示真实显示名称、用户名和头像颜色。
- 当前用户在候选列表中标记为本人。
- 可提及成员范围包括画板所有者以及曾打开该画板的用户。
- 服务端根据当前登录会话写入和校验评论作者身份，避免客户端伪造作者。

### 8.4 评论悬浮按钮

- 画板提供悬浮“评论”按钮，用于打开或关闭评论侧栏。
- 评论按钮支持拖动。
- 拖动超过阈值后不会误触发打开评论侧栏。
- 按钮位置保存在浏览器本地，刷新后保持。
- 窗口尺寸变化时按钮会自动保持在可视区域内。
- 小屏幕下隐藏该悬浮按钮，以减少 UI 遮挡。

### 8.5 只读评论规则

- 只读分享用户可以查看现有评论。
- 只读分享用户不能新建、回复或修改评论。
- 只读用户尝试使用评论编辑入口时显示只读提示。

## 9. 图片、附件和链接内容

### 9.1 本地资源上传

- 画板媒体通过 Drawly 资源接口上传。
- 资源上传和下载均要求用户登录。
- 文件名经过安全字符处理，并附加唯一 ID 防止重名覆盖。
- 资源文件保存在本地 `.data/assets/` 目录或容器数据卷中。
- tldraw 的 `maxAssetSize` 设置为 `100 * 1024 * 1024`，单个导入资源最大 100MB。
- 资源响应设置禁止内容嗅探和脚本执行的安全响应头。

### 9.2 链接卡片预览

- 将 URL 创建为书签卡片时，服务端获取网页预览信息。
- 支持读取网页标题、描述、Open Graph 图片和站点图标。
- 仅允许 HTTP 和 HTTPS 地址。
- 服务端请求超时为 5 秒。
- 预览页面最多读取 512KB 内容。
- 预览失败时仍保留基础链接卡片，不阻断画板操作。

## 10. 数据持久化

### 10.1 数据位置

默认本地数据目录为项目下的 `.data/`：

```text
.data/
├── app.db       # 用户、Session、画板、分享及最近使用记录
├── rooms/       # 每个画板一个 SQLite 房间数据库
└── assets/      # 用户上传的图片和附件
```

可通过 `DRAWLY_DATA_DIR` 修改服务端数据目录。

### 10.2 应用数据库

`app.db` 当前保存：

- 用户账号及密码哈希。
- 登录 Session 及过期时间。
- 画板元数据、所有者、状态和时间信息。
- 只读及可编辑分享链接。
- 每个用户的画板最近打开记录。

数据库启用 WAL 日志模式、外键约束和 5 秒忙等待。

### 10.3 房间数据库

- 每个画板使用独立 SQLite 文件。
- 保存 tldraw 文档记录、页面、图形、协作对象和评论对象。
- 评论对象类型包括评论、评论线程和评论回应。
- 复制画板时通过 SQLite 备份复制完整房间数据库。

## 11. 网络与本地部署

### 11.1 开发模式

- `npm run dev` 同时启动前端和服务端。
- 前端默认监听 `0.0.0.0:5757`。
- API 和 WebSocket 默认监听 `0.0.0.0:5858`。
- 局域网用户可通过运行 Drawly 的电脑 IP 访问。
- 未配置 `VITE_SERVER_URL` 时，前端自动使用当前页面主机名连接 5858 端口。
- 开发环境允许来自任意主机名的 5757 端口源站请求，并携带 Cookie。

### 11.2 容器部署

- 提供多阶段 `Containerfile`。
- 镜像构建阶段执行 TypeScript 类型检查和前端生产构建。
- 生产容器同时提供 Web 页面、HTTP API 和 WebSocket。
- 容器默认监听 8888 端口。
- 容器使用非 root 的 `node` 用户运行。
- `/data` 作为持久化数据卷。
- 提供 HTTP 健康检查 `/health`。
- 支持 Docker，也可通过 `CONTAINER_ENGINE=podman` 使用 Podman。

### 11.3 运维命令

- `make build`：构建单体镜像。
- `make start` / `make run`：启动应用并挂载持久化数据卷。
- `make stop`：停止并删除容器，保留数据卷。
- `make restart`：重启容器。
- `make logs`：查看持续日志。
- `make status`：查看容器状态。
- `make shell`：进入容器终端。
- `make clean`：删除镜像但保留数据卷。
- `make prune`：删除镜像及数据卷，会清空应用数据。
- `make typecheck`：执行全项目 TypeScript 类型检查。
